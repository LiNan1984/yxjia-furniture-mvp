## 前言

### 对产品设计内部

规范设计行为：不同人对「聊天」的理解差异极大（气泡？输入框？卡片？），协作时整体统一性会参差不齐。本规范把「阿杏是一个住在对话里的导购」这条产品判断，落成可执行的交互规则。

### 对上下游流程

规范开发行为：view 模块（`view-*.js`）复用同一套聊天中枢（`chat-core.js`）和同一个 Markdown 渲染器（`vendor/markdown`，ynet 引擎，见 §4），减少重复实现，保证「在任何页面问一句话」的体验一致。

### 本规范的使用者

1. 产品经理：体验一致性
2. UE：按规范拓展页面
3. UI：按 §0 设计 token 定风格
4. 技术：组件/控件统一（尤其 `chat-core` / `vendor/markdown` / 底部浮窗）
5. 测试：用例体验一致

### 1-1 对话方式

**对话方式分为两种：文字输入和语音输入，默认为文字输入。**

**文字输入场景：**

1. 点击 Composer 输入框 → 唤起键盘；右侧多功能图标（相册）切换成「发送」并置灰；输入第一个字时点亮「发送」。
2. 点击发送 → 用户气泡立即上屏 → 阿杏进入「正在想」占位（三个抖点）→ 流式渲染回答。
3. 生成过程中，「发送」按钮切换成「停止生成」；必须先停止生成才能激活发送。
4. 思考过程中继续输入意图，「停止生成」按钮不变。

**语音输入场景：**

按住 Composer 左侧声波键 → 进入全屏语音页（`view-voice`），按住话筒说话、松手发送；中途想取消可上滑取消。语音页让位 Composer（语音本身就是另一种聊天模态）。

> MVP 边界：语音导购有独立全屏 `view-voice`，「语音不离开 Chat」是远期目标。

### 1-2 底部浮窗（上传客厅照）

**使用场景：** 上传客厅照、选示例房间——入口多（首页上传卡 / Composer 相册键 / AI 回复里的「拍照试摆」按钮）、内容重（预览 + 相机 + 相册 + 示例房间 + 拍照提示），做成全屏页会让人「离开对话」。

**动效方式：** 浮层从底部从下往上进入，从上往下退出，过渡时间 **0.15s**。

**规则：**

1. 浮窗高度最高 **724px**，超出上限支持滚动。
2. 点击蒙版或下拉可直接取消浮窗，过渡时间 0.15s。
3. 取消不销毁已选房间：`ctx.state.roomUrl` 保留，下次打开浮窗直接显示上次的客厅。
4. 浮窗打开时 Composer 保持可见但失焦（键盘不顶浮窗）。

**结论：`#view-upload` 不作为独立全屏 view 存在。** 上传能力收进底部浮窗；`view-upload` 路由仅作 hash 直入/测试兜底。

### 1-3 停止生成

**规则：**

1. 未生成答复前，用户可点「停止生成」中断；中断后「正在想」占位消失，已生成的部分保留为一条不完整气泡。
2. 中断后上下文带一个 `assistant` 截断标记，避免下一轮上下文错位。

### 1-4 点击区域

**规则：** 按「所见即所得」，一个显著按钮/图标/头像/一条表单内容，用户都会默认可点。实际点击区域要比可见元素更大，增强容错。

**落地要求：**

- 所有可点元素最小 `min-height:44px`（老人友好）。
- 同一区域有多个可操作按钮时，实际点击区域取按钮所在整区，降低误触。
- Composer 的三个按钮（声波 / 相册 / 更多）各自 ≥34px 且间距 ≥8px。

### 1-5 多意图识别

**规则：** 识别到一次多种意图时，返回统一兜底话术引导拆解，同时给出一个意图的回复。

**阿杏兜底话术：**

> 为了帮您挑得准，咱们一次说一件事会更好哦～

（后端 `GUIDE_INSTRUCTIONS` 已约束；前端不特殊处理。）

### 1-6 常驻对话（阿杏新增，优先级最高）

**规则：**

1. **任何状态都不能让用户失去 Chat。** 顾客在任何页面（首页 / 商品 / 3D / 方案 / 我的 / 语音 / 上传浮窗 / 预约）发一句话，都必须立刻在自己的屏幕上看**自己发的那条 + 阿杏的回复**。
2. 非对话页收到发送动作时，**自动切回对话流**（`view-home`），新消息追加到末尾并滚到底。
3. 对话流由 app shell 级中枢（`chat-core.js`）持有，不随 view 卸载销毁；`view-home` 只负责它自己的静态首屏结构（hero / 上传卡 / 你可以这样问 / 四大功能）。
4. 「阿杏正在想」占位是全对话流唯一的，重复触发不叠加。

### 1-7 智能体引导

**使用规则：** 为了更好地服务用户，阿杏在特定场景主动延续或补充用户意图，减少追问。

**使用场景：**

1. 根据用户习惯在首页主动追问感兴趣的功能（「你可以这样问」）。
2. 针对用户的问题进行补充和延续，猜用户所想。
3. 针对模糊询问给出相似回答，同时保留纠错能力。
4. 用户意图命中非 AI 功能时，引导用户换个话题 / 打店里电话。

**智能体引导样式两种：**

- **样式一（气泡样式，适用于卡片下方展示）**：「你可以这样问」——标题 + chips + 换一换。**沉在首页对话流最底部。**
- **样式二（卡片样式，适用于对话较多时展示）**：「猜您还想问」——阿杏回复气泡下方追加 2 条追问 chip，点击即发送。

### 1-8 非 AI 功能兜底

**规则：** 命中「阿杏干不了的事」（改价、定制尺寸、查物流、售后纠纷……），统一兜底话术 + 门店电话：

> 这个我得请店里同事来办～您打 **13359140982**，或者点右上角直接打给店里。

### 1-9 超时中断

**规则：**

1. 单次问答超时（前端 20s UI 竞速、后端 60s 硬超时）：toast 翻成人话 + 时间线补一句兜底话术，**时间线不能出现问了没答的空洞**。
2. 网络或系统异常：统一 toast 提示。

### 1-10 语音播报

**规则：** 对文本生成的内容固定播报（TTS），对卡片展示的内容按需播报（只播标题）。

## 2 组件控件

| 2-1 聊天气泡 | 2-4 阿杏卡片（带头像） |
|---|---|
| 2-2 Composer | 2-5 商品卡片 |
| 2-3 底部浮窗 | 2-6 对话框 |

### 2-1 聊天气泡

**使用规则：**

1. 气泡分两侧：阿杏在**左**（头像 + 白底气泡），用户在**右**（头像 + 杏色浅底气泡）。
2. 每条气泡带**时间戳**（`HH:mm`），显示在气泡下方，10px、灰色。
3. 用户侧头像：未登录用「我」字圆；已登录用顾客上传过的头像（MVP 无头像上传 → 固定「我」字圆）。
4. 阿杏气泡内容走 **Markdown 渲染**（见 §4），不用纯文本。
5. 「正在想」占位：三个抖点，`letter-spacing:.24em`。

**组成要素：** 头像 + 气泡正文 + 时间戳（可选：追问 chips）。

### 2-2 Composer

**使用规则：**

1. 常驻在 Tab 上方，除全屏语音页外**所有 view 都在场**。
2. 结构：`[声波] [输入框 + 相册/发送] [更多]`。
3. 输入框 placeholder：`发消息或按住说话…`；生成中变为 `阿杏正在想…`。
4. 有字 → 显示发送、收起相册；清空 → 反过来。
5. 回车即发送（`isComposing` 时不吃回车，避免输入法组字被打断）。

### 2-3 底部浮窗

见 §1-2。

### 2-4 阿杏卡片（带头像）——本轮核心

**使用规则：**

1. **所有由阿杏产出/代言的卡片，左边必须有阿杏头像。** 这是「谁在跟你说话」的视觉锚点，也统一了首页与对话流的视觉语言。
2. 覆盖范围：上传客厅照卡、上次试摆结果卡、商品推荐卡、预约卡、方案卡。
3. 头像尺寸：卡片内 30px（`.ax-msg__ava` 同级），与气泡时间线眼睛对齐。
4. 卡片本体仍是白底 + 1px 石灰边 + 小圆角；头像在卡片**外侧左侧**，不占卡片内 padding。
5. 纯功能入口（底部 Tab、Composer 按钮、返回键）**不加头像**——只有「阿杏在说话」性质的块才加。

### 2-5 商品卡片

**使用规则：**

1. 默认 `speaker: true`——带阿杏头像前缀（见 §2-4）。
2. 组成：主图（1:1）+ 名称 + 规格/副标题 + 价格 + 操作（详情 / 选它）。
3. 价格用 `--c-apricot-deep`；库存异常加 badge。
4. 卡片操作区 `min-height:44px`。

### 2-6 对话框

**使用规则：** 最高层级控件，中断用户当前操作，尽量减少使用。

1. 严重影响的重要提醒必须用对话框（例：删方案、退出登录）。
2. 错误早提示：即时校验 + toast，不弹对话框。
3. 二次确认：给用户反悔机会。

## 3 公共模块

| 3-1 聊天上下文 | 3-2 限流与人话 |
|---|---|
| 3-3 空状态 | 3-4 异常提示 |

### 3-1 聊天上下文

**规则：**

1. Composer 随身携带最近 **6 轮**上下文，支撑「换一个 / 便宜点」这类指代；后端上限 20 轮。
2. 超过 6 轮从最早的一轮起丢。
3. 刷新页面后上下文清空（MVP 无会话持久化）——但**商品/房间/手机号等跨页状态走 localStorage 持久化**。

### 3-2 限流与人话

**规则：** 后端 429/503 一律翻成人话，并给替代路径：

- 429：`今天体验次数已用完，欢迎到店看实物`
- 503：`服务暂时不可用，请稍后再试`
- 任何失败：toast + 时间线补一句兜底话术（不能有空洞）

### 3-3 空状态

**规则：** 无数据时用 `.empty` 虚线框 + 一句人话 + 一个动作按钮。不留白屏、不放破碎图。

### 3-4 异常提示

**规则：** 图片加载失败 → 退兜底图 → 再失败换文字占位，不留破图、不无限重试。

## 4 Markdown 渲染规范

### 4-1 引擎选择

**Vendor `ynet-render-markdown` 的 H5 核心**（不引 npm / CDN）。把 `ynet-render-markdown` 仓库 `H5/markdown-render/src` 的源文件（`parser` / `inline` / `render` / `registries` / `style` / `types`，约 1060 LOC，纯浏览器 ESM、零运行时依赖、全走 `createElement`+`textContent`、无 `innerHTML`，且自带 `MarkdownStreamEngine` 流式缓冲 + node-keyed diff）拷进 `src/axing/js/vendor/markdown/*.js`，聊天层接 `MarkdownRenderView` + `MarkdownStreamEngine`。

**为什么 vendor 而不是 npm install**：CLAUDE.md 铁律「生产 rsync `src/` 即可用，无需在服务器 `npm install`」+「不引前端框架」。vendor 是把源文件纳入 `src/` 一起 rsync，部署链路不变；装 npm 包会破坏这条链路。相对导入即可，**不需要 importmap**（与 three.js 不同）。

**IP 归属**：`ynet-render-markdown` 无 LICENSE 文件（作者 belink.com）。需求方已确认 IP 归属本方公司 → 允许 vendor 源文件入 `src/`。若日后归类存疑，退回方案：按 §4-2 语法清单重写一份约 200 行自研 `markdown.js`（同流式 key diff 思路，契约不变）。

### 4-2 语法支持清单

| 块级 | 行内 |
|---|---|
| 标题 `#` ~ `######` | 加粗 `**x**` / `__x__` |
| 段落（连续行合并为空格） | 斜体 `*x*` |
| 无序列表 `-` / `*` | 行内代码 `` `x` `` |
| 有序列表 `1.` | 链接 `[t](url)` |
| 引用块 `>` | 删除线 `~~x~~` |
| 代码块 ` ``` ` | 分割线 `---` |
| 表格 `\| a \| b \|` | 转义 `\*` |

### 4-3 流式渲染

**规则：**

1. SSE `/api/chat/guide/stream` 返回 `status / thinking / tool / delta / done` 五类事件。
2. `delta` 逐段喂给流式渲染器：**只重画未稳定节点**（未闭合代码块 / 最后一个未以空行结束的节点 `stable:false`），已稳定节点不重建——避免流式时表格/列表抖动。
3. `thinking` 折叠成「阿杏正在想」占位，不展示给用户（豆包 `reasoning_content` 是内部推理）。
4. `tool` 折叠成一句人话提示（例：`正在查在售商品…`）。
5. `done` 用完整回复做一次全量标准化渲染，兜住流式截断。

### 4-4 安全

**规则：** 渲染输出**只走 DOM API 建节点，禁止 `innerHTML` 赋原始 Markdown**。链接 `href` 只允许 `http/https/tel`，`javascript:` 一律降级为纯文本。

### 4-5 样式

Vendor 版引擎节点默认挂 `.ynet-md-*` 类并自带一份 light+blue 的 `<style>`（链接 `#2F7CF6`、引用底 `#F4F8FF`）。**不在渲染器源码里改色**——只在 `src/axing/css/axing.css` 覆写这些类到 §0 token；自研退回方案则统一用 `.md-*` 类。颜色全部走 §0 token，禁止写死色值。

```
