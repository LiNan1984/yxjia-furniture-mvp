## 一、概念与策略

### 这个服务到底是什么
「虚拟摆放 / AR 预览」：顾客用手机拍一张自家客厅 → 你用 AI 把店里某款沙发合成进这张客厅照片 → 顾客直接看到"这款沙发摆在我家长啥样" → 大幅降低决策门槛，进店/下单转化率提升。

### 为什么对县城家具店特别有效
1. **痛点准**：买沙发最大顾虑是"摆我家会不会丑 / 尺寸合不合适"。一张合成图直接打消顾虑。
2. **信任高**：本地实体店 + 真实地址 + 电话，比纯网店可信。
3. **传播强**：合成图天然适合发朋友圈、抖音、小红书，自带"好玩 + 实用"属性。
4. **成本低**：AI 合成一张图几毛到几块钱，比雇人 3D 建模便宜得多。

### 一句话定位
**「银杏家具·在线试摆——发张客厅照片，沙发先搬进你家看看，喜欢再来店里坐。」**

## 四、把"店里沙发"合成进"顾客家照片"——真实操作流程

这是整个服务的**技术核心**。gpt-image-2 支持图像编辑（多图参考），可把指定沙发放进指定客厅。

### 工作流
1. 顾客发来客厅照片（A）。
2. 你从店里沙发图册选一款，有该沙发的透明底/白底商品图（B）。
3. 调用图像编辑接口，输入 A＋B 两张参考图 + 指令"把这款沙发自然摆进这个客厅的电视柜前方，保持光线和透视一致"。
4. AI 返回合成图，发给顾客。

### curl 模板（图像编辑 / 多图参考）
> 需要支持 gpt-image-2 编辑接口的平台。`<你的图片接口域名>` 和 `<KEY>` 替换为真正可用的图片生成平台。
```bash
curl https://<你的图片接口域名>/v1/images/edits \
  -H "Authorization: Bearer <KEY>" \
  -F 'model=gpt-image-2' \
  -F 'image[]=@/path/to/顾客客厅.jpg' \
  -F 'image[]=@/path/to/沙发商品图.png' \
  -F 'prompt=把第二张图里的米灰色布艺沙发，自然摆放到第一张图客厅的电视柜前方地板上，沙发正面朝向镜头，保持与原图一致的光线方向、透视和地板阴影，画面真实自然，不要改变客厅其他家具和墙面' \
  -F 'size=1536x1024' \
  -F 'n=1'
```
说明：
- `image[]` 传多张参考图（先客厅、后沙发）。
- prompt 里**强调"保持光线/透视/阴影一致"**，这是合成不露假的关键。
- 想要更稳的效果，可在 prompt 指定沙发大致位置（"电视柜前方居中"）和尺寸（"三人位"）。

### 顾客引导话术（发图时配套）
> "您好～把您家客厅拍一张发我就行，正面拍、把电视柜和沙发位拍全，光线亮一点最好。我帮您把店里的沙发'搬'进去看看效果，挑中喜欢的再来店里试坐。"

## 六、图片生成平台说明（twofishai 不可用的替代方案）

经实测：
- ❌ **twofishai.com**：`/v1/models` 仅返回 Claude 文本模型（claude-fable-5 / opus / sonnet / haiku 等），**无任何图片模型**，`/v1/images/generations` 返回 "Images API is not supported for this platform"。该平台不能用于 gpt-image-2。
- ✅ 可用方向（任选其一，需自备 key）：
  1. **OpenAI 官方**：模型用 `gpt-image-1`（OpenAI 当前图片模型；"gpt-image-2" 多为部分中转站别名）。端点 `https://api.openai.com/v1/images/generations` 和 `/v1/images/edits`。
  2. **支持 gpt-image-2 的中转站**：需确认该站 `/v1/models` 里确实列出 gpt-image-2 / gpt-image-1。

### 通用可用 curl（文本生图，拿到可用平台后直接用）
```bash
curl https://<可用平台>/v1/images/generations \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <KEY>" \
  -d '{
    "model": "gpt-image-2",
    "prompt": "（粘贴上面第三节任意提示词）",
    "n": 1,
    "size": "1024x1536"
  }'
```

> 建议先调 `GET /v1/models` 确认平台是否真的有 gpt-image-2 / gpt-image-1，再下单生成，避免浪费额度。

## 七、网站开发方案（"也可以开发一个网站"）

### 网站定位
一个极简的「在线试摆」落地页 + 家具目录，让顾客自助上传客厅照片、选沙发、看效果、留电话。

### 页面结构
1. **首页**：一句主标题「发张照片，沙发先搬进你家」+ 上传按钮 + 店铺信任信息（地址/电话/实体店照片）。
2. **家具目录**：沙发 / 柜子 / 床 三类，每款一张商品图 + 名称 + 尺寸 + "试摆这款"按钮。
3. **在线试摆页**：上传客厅照 → 选一款沙发 → 提交 →（后台调 AI 合成）→ 展示对比图 → "满意？留个电话，店里联系你"。
4. **案例展示**：放几张已完成的试摆对比图（用第五节提示词5生成）做信任背书。
5. **联系我们**：地址、电话、营业时间、到店导航。

### 技术建议（轻量、好部署）
- 前端：单页 HTML + 简单 JS（或 Next.js），移动端优先（顾客都用手机）。
- 后端：一个轻接口接收图片，调用图片生成 API 做合成，返回结果图。
- 部署：可部署到你提供的服务器（见第八节）。
- **省事方案**：前期甚至不用网站，直接**微信加好友 + 收图 + 手动跑 AI 合成**跑通流程，验证有客户后再做网站自动化。

### 最小可行流程（MVP，先跑通再说）
```
顾客加微信 → 发客厅照片 → 你在电脑上用 curl/工具合成 → 发回对比图 → 邀约到店
```
这个流程今天就能用，零开发成本。网站是放大器，不是必需。

## 八、基础设施与待办（MCP / 服务器）

### MiniMax MCP（你想用来搜索/出图）
- 现状：已配置在 `~/.claude-mcp/minimax.sh`，从 macOS 钥匙串读 key，但**启动即崩溃**。
- 钥匙串里已有 `MINIMAX_API_KEY`。
- **真实报错**（已抓到）：
  ```
  ModuleNotFoundError: No module named 'mcp.server.fastmcp'
  ```
  根因：`minimax-coding-plan-mcp` 依赖的 Python `mcp` SDK 版本与当前 uv 缓存里解析到的版本不兼容（`FastMCP` 在新 `mcp` 包里的位置变了）。
- **建议修复**（新开会话后执行）：
  1. 修脚本 `~/.claude-mcp/minimax.sh`，把最后一行 `uvx minimax-coding-plan-mcp -y` 改为：
     ```
     uvx --with "mcp>=1.2,<2" minimax-coding-plan-mcp -y
     ```
     强制锁定兼容版本的 `mcp` 依赖。
  2. 若仍报错，清 uv 缓存再试：`uv cache clean minimax-coding-plan-mcp`，然后重跑。
  3. 若包本身版本太老，可去 PyPI 看 `minimax-coding-plan-mcp` 是否发布了新版。
- 即便修好，**当前会话也无法立刻使用**——MCP 工具在会话启动时加载，修好后需**新开一个 Claude Code 会话**才能用上。
