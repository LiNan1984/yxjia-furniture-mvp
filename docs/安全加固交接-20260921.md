## 3. 关键机制（接手必读）

1. **上传双保险**：扩展名黑名单（svg/html/...）+ mime 白名单（jpg/png/webp）+ 魔术字节兜底（文件头 `<svg`/`<!doctype`/`<html`/`<?xml` 一律拒）。`application/octet-stream` 仅在扩展名也在白名单时放行。落盘名用 `safeImageExt` clamp，防双扩展名 `a.jpg.svg`、大小写 `.SVG`。
2. **转义分层**：HTML 文本/属性用 `esc()`；URL 属性用 `esc()` 够用；**内联 JS 字符串字面量必须改 data-* 委托**（esc 挡不住引号突破 JS 上下文）。
3. **IP 限流前提**：所有 IP 限流默认用 `req.socket.remoteAddress`，**只有部署在可信反代后并设 `TRUST_PROXY=1` 才信 XFF**（见 §5-2）。
4. **每用户试摆限额按 userId**：换 IP/换手机号重登绕不过（userId 不变），但换手机号注册新号可重置（见 §5-1）。

## 5. 必须知道的残留项 / 部署门禁（都不是 bug，是权衡）

1. **登录模型是固有弱点**：`/api/auth/login` 是「任意手机号 + 固定 `123456` 自动注册」。因此「只能查自己手机号」和「每用户试摆 20 次」**能被换手机号重登绕过**。CLAUDE.md 已注明验证码 MVP 固定 123456。**根本解 = roadmap v2.2 真短信验证码**，在那之前这些 per-user 限制只是"提高门槛"而非硬边界。
2. **上反代必须设 `TRUST_PROXY=1`**：否则 `remoteAddress` 全是代理 IP → 所有 IP 限流塌成一个桶，且后台防爆破会把真老板锁 15 分钟（可被刻意 DoS）。**请确认 3300 端口是否直连；若套 nginx/Caddy，务必 `TRUST_PROXY=1` 并写进部署清单。**
3. **默认 `admin/123456`**：防爆破锁是唯一屏障，生产建议强制 `ADMIN_PASSWORD` 或启动时告警。
4. **`data/products.json` 有 6 条 "测试新沙发 pytest" 是 HEAD 里已提交的**（非本次产生），会把试摆页撑到 17 张卡片，建议删。本次会话新增的测试数据测试已自清理。
5. **MinIO 凭证疑似不匹配**：`.minio.sys` 与 `.env` 的 `MINIO_ACCESS_KEY=yxjia_admin` 对不上，上传走本地 fallback（项目设计如此，但值得核对）。
6. **Cookie 无 `Secure`**：与 CLAUDE.md「HTTP 优先」一致，上 HTTPS 时需补 `Secure`。
