## 2. 改了什么

### 2.1 三张图同时在场（`src/axing/js/view-tryon.js`）

试摆页原来只显示「结果图 + (按住对比) 房间图」，**家具图从头到尾没露面**，
只有一行文字「家具：聚木财MT50真皮软包床」。顾客无从判断 AI 收到的第二张图
是不是自己以为的那一款，出了问题也无法核对。

- `view-tryon.js:115-126` 新增 `inputsRow`：客厅 / 家具两张缩略图，**并排常驻**。
  生成前是「将要送进去的」，生成后是「刚才送进去的」。
- `view-tryon.js:219-236` `syncInputs()` / `paintInput()`：跟着 `ctx.state` 走，
  缺哪张就摆占位文案（`还没有客厅照` / `还没选家具`），不留破图框。
- `axing.css:278-290` `.ax-ty-inputs` / `.ax-ty-input`：双列 grid，
  caption 用渐变遮罩压在图底部。**只在这一层覆写，`.p-card` 本体不动**。

> ⚠️ 缩略图 caption 上的 `data-label` 是给 `paintInput()` 复位用的
> （占位时要盖掉「你的客厅」这类标签）。删了它，空框上会顶着错标签。

### 2.2 结果话术收敛到一处，不再一律说「摆好了」⭐ 本轮核心

**原来的判断是 `if (data.aiError) 诚实提示 else 说「摆好了」`。**
而兜底出了图时 `aiError` 是 **null** —— 于是 Pollinations 重画的示意图
也被说成「摆好了！这是「X」在你家的样子」。

实测证据（同一轮里量的）：

| | 顾客客厅照 | 「合成结果」 |
|---|---|---|
| 尺寸 | 1448 × 1086（4:3） | 768 × 768（1:1） |
| 16×16 平均像素差 | — | **88**（>60 即「基本是另一张图」） |

顾客拿它下 ¥3000 的单，被骗的是真钱。所以改成语义化的四档：

`src/server.js:302-349`

```js
function genStatus(demoType, hasUrl)          // → success / illustration / fallback / failed
function describeGenResult(demoType, aiError) // → { tone, label, note }  ← 唯一说法
```

四档与文案（前端 / 主站 / 生成记录页**都从这里取**，别再各自拼一套）：

| tone | label | 什么时候 |
|---|---|---|
| `good` | 真合成 | 真拿了客厅照+家具图喂给图像编辑模型 |
| `info` | 示意图，不是你家实景 | 走的 Pollinations（弱 img2img，会把房子重画） |
| `warn` | 左右对比预览 / 历史合成图 / 仅家具图 | 根本没调成上游，拿缓存/拼图顶上去 |
| `bad` | 没出图 | 一张图都没有 |

关键改动：
- **`server.js:950`** Pollinations 的 `demoType` 从 `'ai-composition'` 改回 `'pollinations'`
  （场景图链路 `server.js:1225` 同一处谎报也修了）。
  这一行是整条谎报链的根：`demoType` 决定 `genStatus()` → 决定页面怎么说。
- **`server.js:362` `deriveUpstreamError()`**：兜底出了图时，把 trace 里**第一条失败记录**
  提到 `aiError`。原来只有整个链路抛错才有原因；兜底成功时 `error` 栏是空的，
  店主想排查只能翻日志。四个试摆接口都接上了（`grep deriveUpstreamError src/server.js` → 4 处）。
- **`view-tryon.js:371-410`** `data-tone` 四档横幅 + `.ax-bubble` 里的那句人话
  + 出路按钮：`good` 只给「换个氛围再试」；非 `good` 给「再试一次 / 打店里电话 / 预约到店」。

### 2.3 生成记录：未登录也要看得见（`src/server.js:352-381` / `src/my-generations.html`）

`/api/generations/mine` 要登录 + 按手机号过滤，而匿名试摆的 `userPhone` 是空的
→ **没登录的顾客试了 3 次，一条记录都看不到**，「到底成没成、为什么」只有店主知道。

- **`server.js:352` `normalizeAnonId()`**：只认 `^ax-anon-[0-9a-f]{8,32}$`。
  卡死字符集和长度，免得有人拿它当注入面、或塞 4KB 垃圾把 `generations.json` 撑爆。
- **`server.js:2646` `GET /api/generations/recent?anonId=`**：按浏览器随机串查本机记录，
  每条都带 `resultInfo`（tone/label/note）。拿到一个 anonId 也只能看到它自己那几条。
- **`api.js:27` `getAnonId()`**：`localStorage` 里生成/复用随机串。
  **隐私模式 / localStorage 被禁时返回空串、不报错**，只是少了回看能力。
- `my-generations.html`：未登录时回落匿名记录（不再一刀切弹登录墙）；
  新增 `illustration` 徽章档；`resultInfo` 的一句话结论直接摆出来，
  不用顾客自己展开 trace 拼。

### 2.4 顺手修的两个既有 bug

**① `server.js:2396` 生产时区 bug（每天影响 8 小时）**
「到店日期不能早于今天」用的是 `new Date().toISOString().slice(0,10)` = **UTC 日期**，
而顾客端 `view-booking.js:30 todayLocal()` 用本地日期。北京时间每天 **00:00-08:00**
之间 UTC 还停在昨天 → 顾客约「今天」被 400 拒绝。门店 9:00 开门，
**正好把早班那拨想预约的人挡在门外**。已改成本地日期。
三个测试文件的 `today()` 同样修正（`axing.test.js` / `axing-admin.test.js` /
`e2e-customer-voice-booking.test.js`）。

**② `axing.css:151` `.btn` 内 SVG 没尺寸约束**
`ui.js icon()` 造出来的是 `<svg class="ico"><use>>`，没有 width/height。
实测试摆页「立即生成」被撑到 **184px 高**（同参数的「去挑家具」只有 54px），
390×844 上一屏被吃掉 1/4。补了一条通用下限 `.btn > .ico`。
**这个坑不限于试摆页** —— 全站任何 `.btn` 里塞 `icon()` 都可能中。

**提交前先 `git diff` 看清楚再挑文件**，别把别人半成品固化进历史。

### 6.2 twofishai 的 key 是同一把，别浪费时间去换

`.env` 里的 `TWO_FISH_API_KEY` 和老板在对话里给的那把是**同一把**
（都是 `sk-669351d3a…` 开头）。我直接打了上游验证：

| 请求 | 结果 |
|---|---|
| `GET /v1/models` | **200**（key 有效） |
| `POST /v1/images/edits`（gpt-image-1 / 1.5 / 2 全试） | **503** `No available compatible accounts` |
| `POST /v1/chat/completions` | **503** `Service temporarily unavailable` |

→ **是厂商账号池空了，不是我们请求姿势的问题。**
`Authorization: Bearer` 和 `x-api-key` 两种 auth 都被接受（它自己的 401 文案说两种都收）。
所以：**别改 header、别换 key、别改 `image[]` 字段名**，那些都不是原因。
老板需要找 twofishai 恢复账号。

CLAUDE.md §9 那条「key 失效时上游回 `403 GROUP_DELETED`」是旧症状，
现在换成了 `503 No available compatible accounts` —— 排错别看错。

### 6.3 视觉 MCP 不可用

`mcp__MiniMax__understand_image`（余额不足）和 `mcp__zai-mcp-server__analyze_image`（401）
今天都调不通。要判断「两张图是不是同一张」时我用的替代办法：


**16×16 平均像素差 > 60 基本就是另一张图。** 这个判据在「验证 AI 有没有真的用上顾客的图」时很好用。

### 🟡 2. `tmpfiles.org` 隐私问题（我这轮撞见但没动）

`server.js:1052 callPollinations()`（上传动作在 `:1061`）会把顾客的客厅照上传到 **tmpfiles.org**
（公共匿名文件托管）再喂给 AI。也就是说主路径断掉、走到兜底时，
**顾客的家照会落在一个公开 URL 上**。

跟这轮的「诚实」是同一类问题：我们嘴上说「AI 暂不可用」，
照片却已经出门了。一家靠「顾客发客厅照」做卖点的店，这个值得处理
（加开关 / 改私有传递 / 至少让顾客知道）。**要不要改、怎么改是产品决策，等老板定。**

### 🟢 3. `default-room-bed.jpg` 数据债

`server.js:154` 卧室品类配的示例图从来不存在，代码里三处注释都记着
（`server.js:154` / `view-home.js:47` / `index.html:830`），前端有兜底链所以不破图。
要真补上得有一张**真实卧室照片** —— 不能用 AI 图冒充样板间。
