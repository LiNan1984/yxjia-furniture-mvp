## 1. 模块契约

### 1.1 Markdown（vendor ynet 引擎，零 npm / 零 importmap）

**做法（spec v1.1 §4-1 决策）**：把 `ynet-render-markdown/H5/markdown-render/dist/` 里编译好的纯 ESM JS（`parser.js` `inline.js` `registries.js` `style.js` `types.js`，`dist` 与 `src` 同日构建、非陈旧）拷进 `src/axing/js/vendor/markdown/`，再用相对导入写一层阿杏适配 `src/axing/js/markdown.js`。

```js
// src/axing/js/markdown.js（阿杏适配层，唯一对外的 markdown 入口）
export function parseMarkdown(src) -> { nodes }              // 直接 re-export vendor
export function renderMarkdown(src) -> DocumentFragment      // .md-* 类，见 §4-5
export function createMarkdownStream(host) -> {
  push(delta): void,     // 喂 MarkdownStreamEngine，只重画未稳定节点
  reset(): void,
  finish(fullText): void,
}
```

**硬约束：**

1. **禁止调用 vendor 的 `injectMarkdownStyle()`** —— 它注入 `#2F7CF6` 蓝 / `#B42318` 红 / `#F4F8FF` 浅蓝底，违反两色调铁律。阿杏的样式全部走 `css/markdown.css`。
2. 节点类名必须是 `.md-*`（spec §4-5）：`.md-h1..h6` `.md-p` `.md-ul` `.md-ol` `.md-li` `.md-quote` `.md-pre` `.md-code` `.md-table` `.md-thead` `.md-tr` `.md-th` `.md-td` `.md-hr` `.md-strong` `.md-em` `.md-del` `.md-codeinline` `.md-a`。vendor 产出的 `ynet-md-*` 类**必须改写**成 `md-*`（在渲染层遍历改名即可，复用 ynet 的行内解析不必重写）。
3. 只 import 需要的 vendor 文件；`dist/render.js`（自带 ynet 样式的渲染器）**不要 import**。
4. 安全：只走 `createElement` / `createTextNode` / `textContent`；链接 `href` 仅允许 `http:` `https:` `tel:`，`javascript:` 等降级为纯文本。
5. 流式接 vendor 的 `MarkdownStreamEngine`；`done` 时用完整文本 `finish()` 做一次全量标准化渲染。

**验收**：`node src/axing/tests/markdown.smoke.mjs` 必须 0 退出码，覆盖：标题层级、表格、引用、代码块、无序/有序列表、粗斜体/行内代码/删除线/链接、**流式半截表格**（`| 项目 | 详情 |` 无分隔行时不得崩）、`<script>` 与 `javascript:` 注入被中和、渲染结果里**不出现** `ynet-md` 字样、**不出现** `#2F7CF6`/`#B42318` 字样。


### 1.2 `js/chat-core.js`（新建）——常驻对话中枢（P2 核心）

```js
export function initChat(ctx) -> {
  send(text /* string */): Promise<void>,
  stop(): void,
  appendUser(text): void,
  appendAi(markdown, opts? /* { followups?: string[] } */): void,
  setThinking(on): void,
  isBusy(): boolean,
  attachTimeline(host /* HTMLElement */): void,   // view-home mount 时调用
  detachTimeline(): void,
  host: HTMLElement | null,
}
```

**行为铁律：**

1. `send(text)` 的第一步：若 `ctx.current !== 'view-home'`，先 `await ctx.go('view-home')` 再 append。**这是 P2 的修复点。**
2. 消息持久化：`state.messages` 存内存（不落 localStorage），`attachTimeline` 时把已有消息一次性渲染进新 host。
3. `send` 流程：`appendUser(text)` → `setThinking(true)` → `ctx.api.chatGuideStream({message, history}, handlers)` → `appendAi(reply)` → `setThinking(false)`。
4. `thinking` / `tool` 事件只影响占位气泡文案（`阿杏正在想…` / `正在查在售商品…`），不上屏。
5. `stop()` 后：占位消失，已收到的 delta 保留为一条不完整气泡；上下文补一个截断的 `assistant` 标记。
6. 超时 20s UI 竞速（`AbortController`，底层请求自行结束）。任何失败：`ctx.toast(ctx.humanError(err))` + `appendAi(兜底话术)`，**时间线不能出现问了没答的空洞**。
7. 历史随身携带最近 **6 轮**（`{role, content}`），`content` 截断到 2000 字。
8. 时间线 DOM：每条消息 = `div.ax-msg.ax-msg--ai|user` > `div.ax-msg__ava` + `div.ax-msg__col` > `div.ax-msg__bubble` + `div.ax-msg__time`。AI 侧气泡内容走 `renderMarkdown()`；用户侧纯文本。时间戳 `HH:mm`。
9. **停止生成**：生成中 `#composerSend` 隐藏、`#composerStop` 显示；结束反过来。两个按钮都要**内联** `style.display` 置 `none`/`''`（类选择器 `display:flex` 会盖掉 UA `[hidden]`）。
10. 每次新消息后把 `#views` 滚到底：`views.scrollTop = views.scrollHeight`。

### 1.3 `js/api.js`（增量）

```js
/** SSE 流式问答；返回 { abort() }。handlers = {onStatus,onThinking,onTool,onDelta,onDone,onError} */
chatGuideStream({ message, history }, handlers) -> { abort(): void }
```

走 `POST /api/chat/guide/stream`，`Content-Type: text/event-stream`，解析 `data: {json}\n\n`。
**保留** `chatGuide(message, history)` 不改（view-voice 在用）。
SSE 事件 → handlers：`status`→`onStatus`、`thinking`→`onThinking`、`tool`→`onTool`、`delta`→`onDelta(text)`、`done`→`onDone(reply)`、`error`→`onError(msg)`。
