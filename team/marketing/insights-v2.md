## 1. 顾客痛点 Top 3（更新版）

> 前提修正：uploads/users/orders 与 v1 完全一致（0 真实顾客），以下仍是"预判的痛点"，但排序依据从"漏斗内体验"转为"漏斗上游——根本没人进来"。

### 顾客痛点 1（原 v1 痛点 2+1 合并、仍居首）：打开货架只有 3 款老沙发，且信息依旧薄
- **变化标注**：v1 后"信息薄"应被 #3 解决，但因旧商品从未跑过 regenerate-copy、31 张新图未入，**顾客看到的内容和 v1 之前一字未变**（products.json 逐字段核对见第 0 节表格）。
- **证据**：3 条商品 `sellingPoints` 均为空；`whole-home-styles.json` 注明只绑 3 款沙发；想买床/柜/桌的顾客首页无货可选。
- **商业损失**：与 v1 相同且在放大——每多积压一天，老板 9/7 那批新品就多闲置一天；全屋搭配、语音导购、聊天导购三条已建好的链路都只能围着 3 张沙发转。

### 顾客痛点 2（新，升位）：这家店"不存在"——无内容、无曝光、无口碑
- **描述**：县城顾客买家具的第一步是刷抖音/问邻居/逛朋友圈，而这个店在线上零内容零痕迹；顾客痛点从"页面体验差"前移为"根本遇不到"。
- **证据**：v1 洞察老板痛点 2 已指出获客归零；本轮新增外部证据——搜狐「知家AI」2026-09-16 文章《一张实拍图，生成十种家装场景：AI 正在改写家居门店的内容运营》指出门店内容生产"卡在一张图上"：上新/换季/不同平台各要一套图，重拍一轮"少则几天多则一两周"，"内容生产成本高、更新慢，正是很多家居门店线上做不动的直接原因"；并引用小红书《2026 年度居住趋势》："适我主义"以 20.4 亿浏览登顶，顾客问的不再是"哪种风格好看"而是"这个家适不适合我的生活"——单一白底/展厅单品图越来越难打动人。
- **商业损失**：docs/方案.md 里朋友圈/抖音/短信文案早已写好，唯独缺图。没有素材 → 文案发不出去 → 0 曝光 → 0 上传/0 订单（当前数据状态正是这个链条的结果）。

### 顾客痛点 3（原 v1 痛点 5，仍在）：下单前"买了后悔怎么办"无人回应
- **变化标注**：v1 明确非目标，未做。无退换/送装说明、无真实买家案例的现状未变。
- **证据**：orders.json 为空说明这"最后 1cm"从未被跨越；方案.md 附录 A③ 三大顾虑（图不对版/回家变丑/退不了）原样成立。
- **商业损失**：同 v1。**但注意**：在 0 流量的现状下，它排在曝光之后——先有人进来，才谈得上最后一厘米。

### 降位说明（与 v1 洞察的对比）
- v1 痛点 3（试摆等待 15-30s）与痛点 4（强制登录）：链路能力未变（`tryonRequirePhone` 仍为 true），**但 0 真实访客意味着这两个"漏斗中部"问题暂无数据、暂不构成主要矛盾**，降位观察。

## 2. 老板痛点 Top 3

### 老板痛点 1：31 张照片积压 11 天，v1 的机器"建好了但没开机"
- **证据**：31 张 `微信图片_20260907*` 一张未动（第 0 节）；`/admin/ai-upload` 已上线可用（dev-log F1，验收含"老板传图→改价→上架"全流程），**不需要任何新代码就能入货**；旧 3 款补文案也只差一个后台按钮（regenerate-copy API 已有，入口没做——dev-log 反馈池 #4）。
- **损失**：老板 9/7 集中拍摄 = 认真进了一批新品，拍照劳动持续零产出；新品卖不动 = 库存压现金流。
- **与 v1 的变化**：从"缺能力"变成"缺操作"——这反而是好消息，说明 v1 选对了题，只差最后一推。这个痛点 v2 的解法主要是**运营动作 + 一个很小的按钮**，不占用主要排期。

### 老板痛点 2：获客动作依旧归零，且"没有素材可发"成为显性卡点（本轮升级为最重）
- **证据**：users/uploads/orders 三份 JSON 自 8/2 后零新增，距最后一条真实数据已 47 天；方案.md 的朋友圈/抖音文案齐备但无图可配；外部证据（知家AI 文章）证明"实拍图转多场景营销图"已在 2026 上海国际家具博览会成为多家厂商的标配功能、酷家乐 AI 等均已 API 化——同行已经在用低成本内容获客，本店连第一张场景图都没有。
- **损失**：门店自然客流是存量，线上获客是增量；增量持续为 0，且老板手里 31 张实拍图本来可以变成内容弹药（文章核心观点："内容生产的起点从约摄影师变成翻素材库"）。

### 老板痛点 3：经营洞察为零（原 v1 老板痛点 3，维持但降位）
- **证据**：uploads.json 11 条、orders.json 0 条——#5/#9（洞察小结 + Server酱）即便做了也**无数据可总结**。
- **损失**：同 v1（识别高意向顾客、及时电话跟进）。**与 v1 的变化**：在 0 流量现状下，它依赖先解决痛点 2（有流量才有数据），故从并列关注降为"获客跑起来之后的下一棒"。

## 3. v2 功能建议

### 推荐：AI能力调研.md **#12 AI 商品场景图生产**（白底/实拍图 → 多风格场景图，供朋友圈/小红书/商品页）

配套一个"数据前菜"（非主功能，见下）。

**做法（落点）**：复用已跑通的 twofishai `v1/images/edits`（gpt-image-2）链路，新增端点（如 `POST /api/admin/products/:id/scene-image`）：取商品主图 → 按预设风格卡（天然白/暖光/夜晚/极简/家庭——`data/presets.json` 5 个试摆预设直接复用，且 whole-home-styles.json 已有"陕南暖居风"本地化风格）生成 1-3 张场景图 → 存 MinIO compositions → 老板在后台挑选/重生成 → 选定图落为该商品的第二张展示图 + 可下载发朋友圈。约束照搬项目既有原则：识别/生成"保持产品轮廓、材质、颜色不变，禁止加品牌标/水印"（知家AI 文章给出的可套用 prompt 公式与"失败时减少变量"经验可直接进 prompt 模板）；照片判断不了的不编造，沿用 v1 诚实性兜底风格。

**为什么是它（对证据）**：
1. **打中当前唯一真瓶颈**：0 真实顾客的根因是 0 曝光，0 曝光的根因是没内容。#12 的产出物就是老板痛点 2 的直接解药——每款商品裂变出 3-5 张场景图，一次上架 34 款就是上百条朋友圈/小红书素材，方案.md 写好的文案立刻能配上图发出去。这是 14 项能力里唯一把"店内资产（31 张实拍图）"直接变成"获客弹药"的。
2. **外部行业验证 + 时效性**：知家AI 2026-09-16 文章（本轮真实检索）论证该玩法已是行业标配（2026 上海家博会多家厂商、酷家乐 AI 十几秒出图），并给出小红书居住趋势数据（"适我主义"20.4 亿浏览）支持"多场景多风格内容 > 单一单品图"。本项目踩点准：实拍图存量、gpt-image-2 edits 能力、风格卡体系三者都已在库。
3. **零新依赖、改动面最小**：不引新 SDK/模型——images/edits 主路径 + Pollinations 兜底与 CLAUDE.md 既定架构完全一致（且 CLAUDE.md 第 9 节明确图像勿迁阶跃，本方案不涉及）。后台加一个按钮 + 一个端点，规模与 v1 的 regenerate-copy 相当。
4. **反哺顾客痛点 1 与 3**：每款商品多一张"摆在家里"的场景图，商品页信息变厚；"图不对版/回家变丑"顾虑被"这张图就是用你家沙发真图合成的"部分回应——一鱼三吃。
5. **与其他候选的对比**：
   - **#1 全屋搭配师**：逻辑已由 Phase 1 建好，但 skuBinding 只有 3 款沙发——被货架卡死。正确顺序是先补货架（运营）再喂智能，#1 应排 v3（等货架 10+ 款后价值翻倍）。
   - **#4 合成图自检**：0 真实用户，翻车率无从度量——沿用 v1 洞察对它的否决理由，继续挂起（可做顺手件）。
   - **#5/#9 洞察小结/微信推送**：0 订单 0 上传，无数据可读，做了是空转；获客跑起来后是 v3 首选。
   - **#8 挽单 / #2 多轮导购 / 语音接入新字段**：都以"有访客"为前提；其中"语音/聊天导购接入 suitableFor/placementTip"是 dev-log 反馈池 #3 的一行 prompt 改动，**建议作为顺手件**（见下），但不足以撑起一个版本。
   - **#11 AR / #13 短视频口播**：战略级，依赖流量和素材基础，v2 不碰。

**配套"数据前菜"（v2 验收的一部分，工作量约半天）**：
- ① 运营动作：老板用现有 `/admin/ai-upload` 把 31 张图逐张入库（每张约半分钟）——**不写代码**，作为 v2 验收的运营 KPI；dev 可选做批量扫描脚本（v1 spec 的可选加分项，全部落"下架"待老板确认，不进验收）。
- ② 小代码件：`/admin/products` 列表加"重新生成文案"按钮（调已有 regenerate-copy API，dev-log 反馈池 #4），跑一遍旧 3 款，四件套补齐。
- ③ 顺手件：语音/聊天导购 prompt 的商品库行加上 `suitableFor`/`placementTip`（dev-log 反馈池 #3，一行改动）。

**预期效果（可量化）**：
- 货架 SKU：3 → 34（31 张入库 + 旧 3 款保留）。
- 商品页四件套填充率：0% → 100%（34/34）。
- 营销素材：0 张场景图 → 每款 1-3 张、首批 ≥34 张可发朋友圈/小红书。
- 北极星指标（v2 唯一要动的数字）：**uploads.json 里"非测试手机号"的记录数从 0 → ≥1**，以及老板实际发出的朋友圈条数（素材 ready 是前提）。

## 4. 给产品角色 P 的交接

1. **v2 主菜**：把 #12 做成"商品场景图工厂"——`/api/admin/products/:id/scene-image`（requireAdmin，复用 twofishai images/edits 与 presets.json 风格卡 + whole-home 风格），后台商品列表/详情加"生成场景图"入口，生成后老板可挑选、可下载、可选为商品副图。prompt 约束两条硬线：①保持产品本体不变（轮廓/材质/颜色，禁止加标加水印）；②诚实性——生成的图标注"AI 合成场景，仅供参考"再对外发（与项目"不说假话"原则及知家AI 文章"输出是营销展示图、不等于真实施工效果"的边界一致）。验收标准一句话：**老板能从 34 款在售商品里任选一款，两分钟内得到一张能直接发朋友圈的场景图**。
2. **三件小活一并排进 v2**（都在 dev-log-v1 反馈池）：`/admin/products` 加 regenerate-copy 按钮；旧 3 款跑一遍补齐四件套；导购 prompt 接入 suitableFor/placementTip。
3. **运营 KPI 交给老板/主控，不进 dev 排期**：31 张图用 ai-upload 逐张入货架；可选项是批量扫描脚本（落"下架"待审，spec-v1 已定性为加分项）。
4. **明确不做**：#1 全屋搭配扩展（等货架 ≥10 款）、#4 自检、#5/#9 洞察推送、#8 挽单、#11/#13——理由见上节，避免 v2 重蹈"能力先行、数据不动"的覆辙。
5. **给 T 的提醒**：场景图端点测试沿用 api-v1 的 mock 模式（STEP_BASE_URL/twofishai 均可用环境变量指向本地 mock），覆盖"图片缺失 404 / 生成失败兜底 / 不覆盖商品主图 / 鉴权"四类；诚实性守护测试（生成文案必带"AI 合成"标注）与 v1 A4 用例同模式。
